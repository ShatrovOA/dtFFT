subroutine test_adaptive_roundtrip(use_z_slab)

DTFFT_BACKEND_ADAPTIVE picks a separate backend for every transposition, so the plan keeps a whole table of them rather than one value.

It is also the case where replaying used to be refused outright: loading forces effort down to DTFFT_ESTIMATE, and an adaptive backend is not something that effort level is ever allowed to choose. Choosing and replaying are different things.

Run both with and without Z-slab: the number of transpositions differs between the two, and with it how much of the per-direction backend table is actually filled in. Only the shorter case can expose a tail that was written to file without being set.
